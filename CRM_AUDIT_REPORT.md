## Critical findings before implementation

1. `AdmissionsController.confirm` has no approval-role restriction. Generic admission create/update and enquiry/follow-up mutations also accept confirmed statuses, bypassing the intended conversion workflow.
2. `AdmissionsService.confirm` checks `admissionNumber` before starting the transaction. Concurrent requests can each create a student. Application creation and enquiry-stage update are separate writes; the frontend repeats the second write unnecessarily.
3. `JwtAuthGuard` trusts signed role claims without checking whether an account has since been disabled or demoted.
4. `safeNext` accepts backslash-based URL forms that can resolve outside the intended origin. Validate with URL origin comparison and reject backslashes/control characters.
5. API pagination already exists, but the enquiry UI fetches every record and filters in the browser. Do not rebuild the list or silently paginate it without updating filters/counts/controls.
6. Browser/server UTC-local date calculations disagree with the school calendar around midnight. Date-only follow-ups and monthly report filters require Asia/Kolkata boundaries.
7. Request failures can render as "No follow-ups" or "All caught up". Unknown data must remain an error, not an empty success state.
8. Public enquiries accept caller-selected source values. ContactForm has different phone validation from the backend and lacks equivalent name/length validation.

## Database inventory and integrity

Existing reusable CRM tables/models: `User`, `RefreshSession`, `AcademicYear`, `ClassLevel`, `Section`, `Student`, `Guardian`, `StudentGuardian`, `Enquiry`, `EnquiryFollowUp`, `Admission`, `FeeType`, `FeeStructure`, `StudentFee`, `Payment`, `AuditLog`, `Sequence`. CMS includes `SiteSetting` and separate content models. These must not be duplicated as `crm_leads`, `parents`, or new login tables.

Existing admissions/lead enum values differ from the requested initial vocabulary. Changing them in frontend constants alone would break validation and existing records. New vocabulary, approved/enrolled separation, year-specific uniqueness and foreign keys need a compatibility/data migration design and review.

Source alone cannot establish table contents, migration deployment, backups, recoverability, data retention compliance or provider delivery. No database URL or secret is included in this report. Do not run destructive migration/seed/reset commands. A dedicated test database is required before running record-creating end-to-end tests.

### Read-only database verification

An explicitly `READ ONLY` transaction inspected schema metadata and migration names only. It found **30 tables (including `_prisma_migrations`), 211 constraints and 80 indexes**. Six migrations are finished, with no unfinished migration recorded. The metadata artifact is `docs/crm-database-audit.json`; it contains no family rows, database connection string or credentials.

The local migration `20261009120000_add_learning_photos` is **not applied**, and the `LearningPhoto` table is absent. This is an existing CMS deployment gap. No migration was applied during this work. Source-model existence must not be mistaken for deployed-table existence.

The deployed `Enquiry.assignedStaffId` and `Admission.enquiryId` are nullable text columns without foreign keys. Their new service validations and row locking reduce API-level integrity risks but do not replace database constraints. Deployed `createdAt` columns are `timestamp without time zone`; the corrected monthly SQL shifts UTC-stored instants to the school calendar before grouping.

## Implementation order

First close confirmed-status, stale-role, duplicate-enrolment, source-validation and redirect defects without schema changes. Then connect enquiry server pagination/filters and correct school-time/error/cache behavior. Add regression tests for those changes. Broader visits, durable notifications, granular permissions, campaigns and document workflows require reviewed additive models and their full API/UI/test integration; this report does not label them complete.
